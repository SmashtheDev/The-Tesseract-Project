# Tesseract Hardware Encryption - Progress Log

## Codebase Patterns
- Rust workspace with crates: crypto, core, cli, vfs, gui, packaging, hardware (new)
- Uses egui 0.28 for GUI
- AES-256-GCM for file encryption (existing), AES-256-XTS for hardware containers (new)
- Argon2id for key derivation
- Multi-level access system (levels 1-4 with independent passwords)
- THC (Tesseract Hardware Container) format for drive encryption
- Hardware crate structure: error.rs, detect.rs, container.rs, crypto.rs, platform/, sed/
- Platform stubs: platform/linux.rs, platform/windows.rs, platform/macos.rs, platform/mod.rs
- SED stubs: sed/opal.rs, sed/mod.rs with OpalStatus, OpalDrive types
- THC header: 4096 bytes, magic "TESS-HWC", version 1, CipherSuite::Aes256Xts
- Dual key derivation: HKDF with "TESSERACT-HARDWARE-KEY" and "TESSERACT-SOFTWARE-KEY" contexts
- DriveType enum: SedOpal, TesseractContainer, Unencrypted, Unknown
- HardwareError: comprehensive error enum with platform hints, recovery checks
- XTS implementation: tesseract-crypto/src/xts.rs, Xts256 re-exported to hardware crate
- XTS key is 64 bytes (two 256-bit AES keys), tweak is sector number as little-endian
